The Agent2Agent protocol,
without the overwhelm

The official documentation at a2a-protocol.org is great and thorough — and a lot to take in when you are just starting out. This is the opposite: one server, one client, roughly 100 lines each, doing one honest round trip so you can see what A2A actually is.

Get the code See the live AgentCard

Why this exists

Most A2A material starts with the full spec: transports, streaming, push notifications, task lifecycles. Useful later. Confusing on day one.

Small enough to read

No framework layers, no orchestration, no LLM. Two files you can read top to bottom in a coffee break.

Always the same answer

The agent ignores what you send and replies identically every time — so nothing distracts from the protocol mechanics.

Real protocol, not pseudo-code

Genuine AgentCard discovery, a real SendMessageRequest, a real completed task with an artifact.

One round trip, start to finish

That is the whole protocol surface this demo touches. Everything else in A2A is built on top of these three moments.

STEP 01

Discover

The client fetches the AgentCard and learns where and how to talk to this agent.

STEP 02

Send

It sends one message. Text is optional — send nothing and the shape of the reply does not change.

STEP 03

Receive

Back comes a completed task: a status message that thanks you, plus an artifact carrying structured JSON.

Try it in two commands

You are already looking at step one — this page is served by the running agent. Open a second terminal for the client. 

uv run python A2A/server.py
Uvicorn running on http://localhost:8001

uv run python A2A/client.py Hi there
Thanks for your message: 'Hi there'.
The result is in the artifact.

Built on the A2A Python SDK. This page itself is not part of the protocol — agents never open it, they read the AgentCard instead.
